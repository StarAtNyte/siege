Can your AI agent’s wallet be drained?

One poisoned email can make an AI agent pay a thief, and payments can’t be undone. SIEGE attacks your agent’s spending rules first, with test money.

  1. Agents act on what they read.

    Email, invoices, web pages.

  2. Attackers hide payment orders in them.

    A forged invoice names a lookalike:

    cloudhost.testnetyour real vendor c1oudhost.testnetthe attacker

  3. SIEGE attacks your spending rules first.

    With tricks like these, to find the rule that leaks:

    • Hidden instruction a buried order
    • Lookalike name one character off
    • Changed address “we moved accounts”
    • Redirected call a contract call that pays someone else
    • Drip many small payments
    • Race payments fired at once

    Give your agent guarded payment tools

    The SIEGE MCP server checks every payment against these rules before it pays. It works with Claude Code, Codex, Cursor or any MCP agent; the agent never holds a key.

    git clone https://github.com/StarAtNyte/siege && cd siege && npm install
claude mcp add siege -e MANDATE="Pay any vendor invoice up to 10 NEAR per transaction." -- node "$PWD/bin/siege-mcp.mjs"

    It exposes siege_pay and siege_check. Without vault keys it pays a mock wallet and says so. Setup for Codex and Cursor

  A public blockchain. SIEGE runs on its test network, so no real money moves.
  A custody wallet for AI agents on NEAR. Its policy is what typical limits means here: per-payment and daily caps, and an allowlist only where your rules name payees.
  SIEGE’s guard sits in front of the wallet. It checks each payment against your rules, and reads who asked for it and why.
  Each round, the attacker builds new attacks from the ones that worked best, against both guards. Thirty rounds.
  The most the guard lets go to payees your rules never named. Named payees don’t count against it.
